## 1. 问题 / 用户 / 目标 / 非目标

### 1.1 问题
一期已交付 13 个 PDF 工具，形成完整纯前端办公工具骨架。但 SEO 流量入口仍集中在 PDF 赛道，体量不足以支撑 3000-5000 日 UV 阶段目标；办公人群高频刚需的图片处理、二维码生成、多媒体轻量工具、办公小工具四大板块均为空白；站点工具生态不完善，用户收藏率与次日留存偏低。

### 1.2 目标用户
- 职场办公人群（996 白领、行政、HR、市场、销售、教师、学生）
- 搜索关键词画像：「图片压缩在线」「JPG转WebP」「证件照换底色」「二维码生成」「二维码批量」「视频压缩」「音频裁剪」「时间戳转换」「密码生成」
- 设备分布：移动端 ≥60%，桌面端 40%；低配置手机需保证流畅

### 1.3 目标
- **流量目标**：二期全部上线后，工具落地页总数从 13 → 约 35+，覆盖图片/二维码/多媒体/办公四大 SEO 高流量赛道，为站点权重与 UV 增长提供增量入口
- **留存目标**：二维码工具（收藏率最高品类）+ 办公小工具（高频随手用）双组合，提升用户收藏率（安装提示点击）与次日回访
- **架构目标**：严格沿用一期 `tools.ts → processors.ts → ToolPageTemplate` 三层扩展架构，**零结构重构、零返工、不打乱一期代码**
- **批次交付目标**：每批次完成即 build → 打 tag → 推送 → 浏览器验证，每批次都可独立上线吃 SEO 流量，不依赖后续批次

### 1.4 非目标
- ❌ **不开发任何后端**：所有工具必须纯前端在浏览器本地完成，不得引入后端 API、云函数、Serverless
- ❌ **不开发用户体系**：不新增注册、登录、会员、积分、次数限制
- ❌ **不开发付费功能**：批次 6 仅预留架构入口（弹窗/授权/提示），不写任何云端功能、不写计费代码
- ❌ **不替换一期技术栈**：不新增 React 替代框架、不引入重量级 UI 库（保持 Tailwind 内联组件风格）
- ❌ **不打乱路由架构**：所有工具必须沿用 ToolPageTemplate，无特殊情况不得新建独立路由页面组件

## 2. 功能需求（按批次 1→6 严格顺序）

> **硬性规则**：必须严格按批次顺序开发，批次 1 未完成并通过验收前，不得动批次 2；批次 2 未完成前，不得动批次 3。每批次对应独立语义化版本号（v1.1.0 ~ v1.6.0）。

### 批次 1 · 图片工具全集（最高优先级｜流量最大，搜索最多，办公刚需最强）
对应分类: `image`（tools.ts 已预留，首页从 ReservedCard 转真实工具卡片）

#### 工具 1.1：图片批量压缩
- 输入格式: JPG / PNG / WebP，支持多文件批量上传（accept: `image/jpeg,image/png,image/webp`，multiple: true）
- 三档压缩模式:
  - **轻度压缩**: 质量 85%，体积↓10~25%，视觉无损
  - **标准压缩**（默认）: 质量 70%，体积↓30~50%，推荐
  - **极致压缩**: 质量 45% + 最长边缩放到 1920px，体积↓60~80%
- 保留原始格式输出，**批量多文件自动打包 ZIP**（单文件直接输出）
- 结果实时显示：每张图压缩前后大小、总压缩率
- 功能边界: 已压缩过的图片再次压缩收益有限；GIF 动图暂不支持；超大 4K+ 单张图在低端手机可能卡顿

#### 工具 1.2：图片批量格式互转
- 输入格式: JPG / PNG / WebP / BMP（accept 全覆盖）
- 输出格式可选: `JPG` / `PNG` / `WebP` / `BMP`（默认原格式保持）
- JPG 支持质量参数 10~100；WebP 支持质量参数 10~100 + 可勾选 lossless 模式
- PNG 转 JPG 时透明区域自动填充白色（可自定义填充色，默认白）
- 多文件打包 ZIP
- 功能边界: 带透明通道 PNG 转 JPG 必须填充底色；GIF / ICO / SVG 等非位图格式暂不支持

#### 工具 1.3：智能证件照工具
- 输入: 单张人像图片（JPG/PNG）
- **尺寸模板预设**（下拉选择，默认一寸）：
  - 一寸 (295×413 px, 25×35 mm)
  - 二寸 (413×579 px, 35×49 mm)
  - 小一寸 (260×378 px)
  - 小二寸 (413×531 px)
  - 大一寸 (390×567 px)
  - 护照签证 (390×567 px，可自定义宽高 px)
- **换底色**（单选，默认原色保留）：
  - 白色 / 蓝色 (#438EDB) / 红色 (#D9383E) / 渐变蓝 / 自定义颜色选择器
  - 换底算法：纯前端 Canvas 按颜色阈值 + 边缘羽化（不是 AI 级精确抠图，功能边界需明确提示）
- 自动裁剪：以图片中心区域按目标比例居中裁剪
- 可选输出: 单张证件照 / 6 张排版（2×3 拼版 A4 可打印）/ 单张+排版打包 ZIP
- **功能边界（重点合规）**: ⚠️ 本工具为颜色阈值级普通换底，非 AI 人像分割，对于复杂背景、卷发边缘、透明纱质衣物可能出现边缘残留；正式证件请使用专业照相馆；不提供任何人脸识别与人像提取能力。

### 批次 2 · 二维码全套工具（次高优先级｜留存最强，传播最强，收藏率最高）
对应分类: `qr`（tools.ts 已预留，首页从 ReservedCard 转真实工具卡片）

#### 工具 2.1：多功能美化二维码生成
- 输入: 任意文本 / URL / WiFi 配置 / vCard / 名片文本框
- **二维码基础参数**: 容错等级 L/M/Q/H（默认 M）、模块像素尺寸 4~20px（默认 10）、外边距 0~20px（默认 4）
- **美化参数**:
  - 前景色/背景色（颜色选择器，支持透明背景）
  - 点阵样式：标准方块 / 圆点 / 圆角方块
  - 定位角样式：标准 / 圆角 / 内嵌方块
  - Logo 图片上传（居中显示，自动按 15% 宽度缩放，容错等级自动提到 H）
  - 预设模板：经典黑白 / 蓝白商务 / 紫粉渐变 / 科技绿 / 橙黄活力
- 输出格式: PNG 高清 / SVG 矢量（两格式并列，用户选择）
- 功能边界: Logo 过大 / 过深可能影响扫码，建议遮挡率 <20%；艺术二维码不保证 100% 扫码器兼容

#### 工具 2.2：图片二维码批量解析 / 识别
- 输入: 多张图片（JPG/PNG/WebP/BMP/GIF 单帧）批量上传
- 解析引擎: 纯前端 `jsQR` 库（**需新增 package.json 依赖**，无其他副作用）
- 输出: 每个文件对应解析结果 → 失败项标注"无法识别"
- 支持在线复制全部结果 + 导出 TXT（每条一行） / JSON（key-value 文件名→内容）
- 功能边界: 严重模糊、倾斜 >30°、点阵损毁、极小码可能无法识别；视频 / PDF 内嵌码需先截图再识别

#### 工具 2.3：批量二维码生成 + 打包下载
- 输入方式二选一:
  - **文本框多行输入**（每行一条内容，自动生成）
  - **TXT / CSV 文件上传**（每行一条，最多 1000 条防止浏览器崩溃）
- 通用参数: 容错等级、尺寸、边距、前景色/背景色（与 2.1 基础参数一致，不含美化点阵）
- 文件名规则: 自动按 `qrcode_0001.png` / `qrcode_自定义前缀_序号.png`
- 全部生成后自动打包 ZIP 下载
- 实时显示进度（XX/XXX 条），可中途取消
- 功能边界: 单批次建议 ≤1000 条，超过浏览器内存压力大；超大数据建议分批

#### 工具 2.4：二维码美化模板优化
- **与 2.1 合并的参数面板增强**（非独立工具）：在 2.1 工具页增加「模板库」区域，提供 6 套预设：
  - 经典黑白、商务蓝、活力橙红、渐变紫粉、科技青绿、极简灰
- 点击模板一键回填所有颜色+点阵+角样式参数
- 非独立工具，不需要单独路由；写进 ToolPageTemplate 的 `OptionsPanel.panels['qr-generate']` 内即可

### 批次 3 · 图片剩余功能补齐（中高优先级｜办公刚需高频，低 BUG 快速上线）
对应分类: `image`（已有分类下扩充工具数量）

#### 工具 3.1：图片批量加水印
- 输入: 多张图片批量（JPG/PNG/WebP/BMP）
- 水印类型: 文字水印 / 图片水印
- **文字水印**: 内容、字号、颜色、透明度 5~100%、旋转角度、位置（9宫格+平铺密集）、字体（默认黑体无衬线）
- **图片水印**: 上传 PNG（支持透明）、水印宽度 20~60% 原图、透明度、位置（9宫格+平铺）
- 批量输出 ZIP，单文件直接输出；保留原图格式
- 功能边界: 平铺密度过高可能影响主图视觉；平铺图片水印模式下性能与图片张数正相关

#### 工具 3.2：长图拼接
- 输入: 多张图片（≥2 张），拖拽排序
- **拼接方向**: 纵向拼接（默认，长图）/ 横向拼接 / 自定义网格（N 列 M 行）
- 可选参数:
  - 图片间距（0~100px）
  - 间距填充色（默认白/透明/自定义）
  - 宽度对齐方式（纵向时：等比缩放到统一宽度 / 保持原图宽度居中）
- 输出格式: JPG / PNG / WebP，质量可调
- 功能边界: 总像素 ≥65535（Canvas 限制）时需自动压缩或提示用户分批；超过 50 张建议分批

#### 工具 3.3：图片分割
- 输入: 单张图片
- 分割方式:
  - **按行列数分割**（N 行 × M 列，平均切）
  - **按固定尺寸切片**（每块 W×H px，剩余边距保留为小块）
- 输出: 所有切片 ZIP 打包，文件名按 `原文件名_行_列.格式`
- 功能边界: 切片数量过多（>500 块）可能内存紧张；仅支持位图，SVG 不支持

#### 工具 3.4：图片旋转裁剪
- 输入: 单张图片
- **旋转**: 90° CW / 90° CCW / 180° / 任意角度（画布自动扩展）
- **翻转**: 水平镜像 / 垂直镜像
- **裁剪**: 可视化输入上/下/左/右像素值 或 按比例百分比（如 10% 四边裁剪），预设 1:1 / 3:4 / 4:3 / 16:9 / 9:16 比例
- 输出格式: 保持原图或选择 JPG/PNG/WebP
- 注：本工具与批次 1 证件照的裁剪区分（证件照按模板比例+人像；本工具通用无预设人像）

#### 工具 3.5：前端轻量 AI 抠图（合规边界完整标注）
- **核心约束**: 100% 纯前端在浏览器运行，**不调用任何云端 API、不上传原图**
- 实现技术方案: 使用 `@imgly/background-removal`（纯 WebAssembly + ONNX，MIT 协议，完全本地运行，不依赖网络）。**需新增 package.json 依赖**（约 30~50MB wasm，放在构建后 chunk，懒加载，不影响首屏）
- 输入: 单张图片（人像 / 物品 / 通用主体）
- 输出模式:
  - 纯透明背景 PNG（默认）
  - 自定义纯色背景（颜色选择器）
  - 自定义上传背景图（按比例填充）
- **功能边界（必须突出展示合规提示，使用红色⚠️样式边框）**:
  - ⚠️ 本工具为纯前端本地运行的轻量 AI 模型，抠图精度低于专业云端服务
  - ⚠️ 对于发丝级细节、半透明物体（纱、玻璃、烟雾）、复杂背景可能有边缘残留
  - ⚠️ 商业级精修需求建议使用专业 Photoshop 人工处理
  - ⚠️ 模型文件在首次加载时约 30~50MB（浏览器本地缓存，后续秒开）
  - ⚠️ **绝不上传任何用户图片**，所有计算均在您的设备 CPU/WebGPU 完成

### 批次 4 · 多媒体轻量工具（中优先级｜补齐生态，丰富站点体量）
新增分类: `media`（tools.ts 中新增 ToolCategory，首页在 image/qr 后新增分类板块；配色 `from-cyan-500 to-blue-500`）

#### 工具 4.1：视频压缩
- 输入: MP4 / WebM / MOV（浏览器原生 `<video>` 可解码格式）
- **技术方案**: 纯前端 `WebCodecs API` + Canvas。降级方案：若浏览器不支持 WebCodecs（Safari 旧版），使用 `MediaRecorder` 录制画布方式。**不写后端、不调用 FFMPEG.wasm（体积过大）**
- 参数: 目标码率 1~12 Mbps / 分辨率缩放 360p / 480p / 720p / 1080p / 保持原分辨率 / 压缩等级滑块（轻度/标准/极致）
- 输出格式: 优先 MP4 H.264（WebCodecs 支持），降级 WebM VP9
- 功能边界: 仅支持浏览器原生可解码视频格式；MKV / AVI / FLV 等先转码后再处理；超大文件（>2GB）建议桌面端软件

#### 工具 4.2：视频裁剪
- 输入: 同 4.1
- 使用原生 `<video>` + 时间轴滑块，UI 显示 开始秒 / 结束秒，预览裁剪段
- 技术方案: WebCodecs 精确按帧裁剪；降级: Canvas + MediaRecorder 实时播放并录制裁剪段（精度±0.5s）
- 输出: 单段裁剪后视频

#### 工具 4.3：视频格式转换
- 输入: 同 4.1
- 输出可选: MP4(H.264) / WebM(VP9) / GIF 动图 / 音频提取 MP3/WAV
- GIF 模式可调帧率 5~24 fps、缩放最长边 320~1080 px
- 功能边界: GIF 文件体积远大于视频，建议 <30 秒短片段转 GIF

#### 工具 4.4：音频压缩
- 输入: MP3 / WAV / OGG / M4A（浏览器可解码格式）
- 技术方案: WebAudio API 解码 → 降采样 / 降位深 → MediaRecorder 或原生编码
- 参数: 比特率 32~320 kbps / 采样率 22050 / 44100 / 48000 Hz / 单声道/立体声
- 输出: MP3（优先） / WAV

#### 工具 4.5：音频裁剪
- 输入: 同 4.4
- UI: 波形显示（使用 AnalyserNode 绘制简易波形）+ 开始/结束秒滑块
- 精确裁剪到毫秒级
- 输出格式: 保持原格式或转 MP3

#### 工具 4.6：音频格式转换
- 输入: 同 4.4
- 输出: MP3 / WAV / OGG / 提取视频音频（与 4.3 提取模式复用代码）
- 功能边界: 浏览器编码能力有限，AAC / FLAC / APE 等格式可能不支持，需要给出提示

### 批次 5 · 办公小工具合集（低优先级｜收尾完善，高留存小工具）
新增分类: `office`（tools.ts 中新增 ToolCategory，首页在 media 后；配色 `from-lime-500 to-green-600`）

#### 工具 5.1：文本批量处理
- **特殊**: 本工具无文件输入要求（可选上传 .txt / .md），主要使用文本框
- 功能模块（多选勾选后一键批量执行）：
  - 去全角半角空格 / 去首尾空格 / 去空行 / 去重复行
  - 脱敏处理：手机号中间 4 位打星 / 邮箱打星 / 身份证打星 / 银行卡打星
  - 繁简转换（纯前端字典，常用 3500 字）
  - 差异对比：左右双文本框，显示增删行（简易 diff 算法）
- 输入: 文本框粘贴 或 TXT/MD 上传；输出: 在线复制或 TXT 下载
- 功能边界: 繁简转换只覆盖常用字，生僻字/古文可能不准；diff 基于行级简易 LCS

#### 工具 5.2：工时计算
- 三种模式:
  - **打卡时间差**: 上班时间 / 下班时间 / 午休时长 → 总工时 + 加班时长（超过 8h 算加班）
  - **累计工时**: 多段起止时间累加 → 总时长（小时+分钟）
  - **工资估算**: 月薪 ÷ 21.75 ÷ 8 = 时薪 × 工时 = 估算工资（仅估算参考）

#### 工具 5.3：时间戳转换
- 双向转换:
  - Unix 时间戳（秒/毫秒）→ 本地时间 / UTC 时间 / 多种格式字符串
  - 日期时间选择器 / 文本 → 10 位秒戳 + 13 位毫秒戳
- 显示当前时间戳（实时刷新，每 1 秒）
- 支持: ISO 8601 / RFC2822 / 常见日期格式自动解析

#### 工具 5.4：密码生成
- 参数: 长度 4~128 位、是否包含大写/小写/数字/特殊符号、是否排除易混字符(0O1Il|)、是否禁止重复字符
- 一键批量生成 1~50 条；支持按强度等级（弱/中/强/超强）预设
- 安全性提示: 密码生成过程完全在浏览器本地，不会通过网络传输任何生成结果

#### 工具 5.5：单位换算
- **分类**: 长度 / 重量 / 面积 / 体积 / 温度 / 时间 / 数据大小（KB/MB/GB/TB/PB）/ 速度（km/h ↔ m/s ↔ mph）/ 角度（度 ↔ 弧度）
- 每个分类 8~20 个常用单位，输入任意一个自动换算其他全部
- 纯前端静态计算，无 API

### 批次 6 · 架构预留（仅搭建结构，暂不开发功能）

## 3. 非功能需求

### 3.1 纯前端约束（红线）
- **rule**: 所有批次新增工具的处理器（processors.ts 新增项）中不得出现任何 `fetch` / `XMLHttpRequest` / `WebSocket` / `navigator.sendBeacon` 调用
- **rule**: 批次 3.5 AI 抠图仅允许使用 `@imgly/background-removal` 本地 WASM 方案，不得引入任何云端 API 密钥
- **rule**: 批次 6 架构预留 modal 不得包含任何网络请求代码

### 3.2 SEO 规范
- **rule**: 每个新增工具在 `tools.ts` 中必须独立配置 `title / description / keywords`，title 必须包含品牌名「MendFile 全能办公工具」
- **rule**: 每个新增工具必须独立落地页 URL 形如 `/tools/image-compress` / `/tools/qr-generate`，canonical 指向 `https://mendfile.com{path}`
- **rule**: 关键词必须覆盖对应高搜索量长尾词（如「图片压缩在线」「在线JPG转WebP」「证件照换底色」「二维码生成免费」等）

### 3.3 UI/UX 规范
- **rule**: 所有工具必须沿用一期 `ToolPageTemplate` 统一架构（上传区→文件列表→参数面板→进度条→下载→预览→功能亮点→边界提示→SEO长文），无特殊情况不得新建独立路由组件
- **rule**: 文件上传区文案、进度条样式、下载按钮文案、chip 样式、card 样式完全复用一期 CSS（index.css + Tailwind），不得引入新 UI 框架 / 新 icon 库（继续使用 emoji 图标）
- **rubric**: 移动端 375px 宽度下，所有表单控件无横向溢出、无文字压叠、上传区可点击区域 ≥44px。0-1-2 分（2=完美，1=1-2处溢出，0=≥3处溢出）；pass 阈值 ≥1
- **rule**: 批次 5 中「无文件输入」工具（工时/时间戳/密码/单位换算）必须在 ToolConfig 中标记 `fileRequired: false`，ToolPageTemplate 对应隐藏上传区+文件列表，直接显示参数面板+结果区

### 3.4 性能规范
- **rule**: 新增依赖需评估体积：二维码解析 `jsQR` ≤30KB gzip；AI 抠图 `@imgly/background-removal` wasm 需配置为懒加载 chunk，首屏不加载
- **rubric**: Lighthouse 首屏（首页）Performance 分数 ≥85（生产构建后本地 preview 测试）。0-1-2 分（2=≥90，1=85~89，0=<85）；pass 阈值 ≥1
- **rule**: 所有工具处理过程必须调用 `onProgress(ratio, msg)` 上报进度（最低 0.05 起步，结束 1.0），进度条不得长时间卡死 0%

### 3.5 合规规范
- **rule**: 每个工具必须在 boundaries 字段列出 ≥2 条功能边界与免责提示，AI 抠图、证件照、云端入口 3 类工具需 ≥4 条并使用红色⚠️强调样式（ amber→red 色卡片）
